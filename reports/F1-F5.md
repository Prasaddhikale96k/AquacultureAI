## F1 - Feeding log, appetite response, DO dip
- `backend/app/services/feeding_service.py:135` - one-tap feeding event,
  append-only `backend/data/feeding_log.jsonl`, farm day, provisional label.
- `backend/app/services/feeding_service.py:157` - grade is computed only after
  a complete +10 min window, from mean track speed in the prior 30 min vs the
  post-feed 10 min:
  - `aggressive >= +30%`
  - `moderate +10% .. +30%`
  - `weak 0% .. +10%`
  - `none < 0%`, or post-feed windows with zero confirmed tracks.
  Missing pre/post data stays `null`; it is never guessed.
- Two consecutive `weak`/`none` feedings -> **R9** English SMS:
  `AquaAI FEED ALERT: Weak feeding response 2 times in a row. Check water/DO/fish health! -AquaAI`
  R9 uses the existing chain, 24 h cooldown, 0 Khatra points.
- `backend/app/services/feeding_service.py:237` - DO feed effect: `s_feed=-0.08`
  only from +2 h to +4 h after the latest feeding, behind
  `AQUA_DO_FEED_DIP=1`. `do_service` exposes additive `feed_evidence` and an
  advisory when estimated DO is already risk/critical.
- `backend/app/routes/feeding_routes.py` - `POST/GET /api/feeding`; POST accepts
  optional `fed_at`/`note`, rejects malformed or >5 min future times.
- Flags: `AQUA_FEED_LOG=1`, `AQUA_FEED_ALERT=1`, `AQUA_DO_FEED_DIP=1`.

## F3 - Daily digest SMS
- `backend/app/services/digest_service.py:114` - English digest:
  `AquaAI {day} {date}: DO {value} at night, behaviour {state}. {n} alerts, risk {k}/100. Feedings today {f}. Median wt n/a g, gain n/a g/day. -AquaAI`
  (<=300 chars). Stale sensors use:
  `AquaAI daily digest: sensor data stale {age}. No DO/behaviour summary. Check ThingSpeak/camera/power. -AquaAI`
- Night DO uses recorded kit readings (20:00-06:00 farm-local); falls back to
  the current estimate only when no kit reading exists.
- `backend/app/services/digest_service.py:159` - one send per farm day at
  `AQUA_DAILY_SMS_TIME=07:00` farm-local, state dedupe, existing SMS chain.
- Weight/gain are `n/a` until F2 growth/biomass lands after CONF-C.
- Flag: `AQUA_DIGEST=1`; loop integration in `backend/alerts.py`.

## F4 - Backup and export
- `backend/app/services/backup_service.py:87` - copies top-level data files
  (JSON/JSONL state, alert log, DO readings, etc.) to
  `backend/data/backups/YYYY-MM-DD/`; never copies `jobs/` or `backups/`.
- Retention: 7 days by default (`AQUA_BACKUP_RETENTION_DAYS`).
- Runs at backend startup and via the existing alert loop; `maybe_backup()`
  dedupes to once per UTC day.
- `backend/app/services/backup_service.py:115` - `GET /api/export/zip`,
  same allow-list, 50 MB cap, `Content-Disposition` attachment.
- Flags: `AQUA_BACKUP=1`, `AQUA_EXPORT=1`; optional `AQUA_BACKUP_DIR`.

## F5 - Diagnostics
- `backend/app/services/diagnostics_service.py:80` - read-only snapshot:
  uptime, farm time/timezone, sensor freshness/error, SMS provider booleans
  plus SMSGate reachability, live engine/model state, auth user/session counts,
  data file count/size/last backup/disk free, and effective flags.
- `GET /api/diagnostics` is auth allow-listed for the settings screen.
- No API keys, phone numbers, session tokens, raw frames or user records are
  returned; sensor `last_entry` is deliberately excluded.
- No new poller, no SMS from diagnostics.
