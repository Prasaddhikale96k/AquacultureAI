# P2 - Dashboard Rebuild

Date: 2026-10-24
Status: **PROVISIONALLY SIGNED OFF** - build green, real-data captures
taken, responsive shell verified. Sensor source was 9 h stale during capture,
so the dashboard shows its honest paused/empty states rather than invented
numbers.

## Part 1 - What changed

### Data layer
- `frontend/src/types/index.ts` - additive contracts for `DoPrediction`,
  `BehaviourSummary`, `FeedingEvent`, `FeedingSummary`.
- `frontend/src/services/api.ts:209` - `getDoPrediction`,
  `getBehaviourSummary`, and `getFeedingSummary` (the feeding call is ready
  for the F1 UI; P2 does not write feeding events).
- `frontend/src/sections/Overview.tsx:99` - rebuilt page loads
  `/api/dashboard`, `/api/do-prediction`, `/api/behaviour/summary`, and
  `/api/predictions` in parallel with `Promise.allSettled`; a failed side
  panel cannot take down the farm snapshot. Auto-refresh is 60 s and skips
  hidden tabs.
- `frontend/src/App.tsx:105` - Overview now receives `setPage`, so every
  quick action is a real navigation, not a dead button.

### Layout
- **DO hero** (`Overview.tsx:170`): conic gauge, mg/L value, likely range,
  confidence, provisional band bar with 2.0 critical / 3.5 watch / 5.0 safe
  markers, input ages, behaviour context, feed advisory, and a next-action
  strip. If inputs are stale it says the estimate is paused; no number is
  substituted.
- **Farm risk** (`Overview.tsx:309`): Khatra score ring, farmer risk label,
  up to three active rules in plain language, and a route to Alerts.
- **Tank & system** (`Overview.tsx:342`): tank profile, sensor freshness, SMS
  gateway state, and four quick actions (Water log, Alerts, Live camera,
  Behaviour).
- **Water-quality grid** (`Overview.tsx:363`): temperature, turbidity in raw
  ADC, manual pH with age, and estimated DO. Stale data changes the heading
  from "right now" to "snapshot".
- **Recent alerts** (`Overview.tsx:377`): farm rules only (OTP/TEST events are
  excluded), rule labels without internal IDs, delivery receipt, and
  "Not an alert?" false-alarm action against the existing endpoint.
- **Dawn outlook** (`Overview.tsx:424`): score or explicit insufficient-data
  reason, 6 h forecast values, 7-day sensor-maturity bar (`span_hours / 168`),
  and the rule components when available.
- Light/dark tokens, 390 px single-column layout, fixed bottom nav clearance,
  skeleton on first load, partial-data banner, and a visible PROVISIONAL pill.
- Farmer-facing wording: "Behaviour score" instead of HBS, "Sensor feed
  needs attention" instead of gate names, plain rule labels instead of R-codes
  in headings. Historical SMS bodies are shown as audit text and may predate
  the English-only directive.

### Limitations / follow-ups
- The live ThingSpeak feed was stale during capture, so the screenshots
  intentionally show paused/empty states. The populated gauge path is driven
  by the same `/api/do-prediction` contract, but was not demonstrated with
  fake data.
- Species and system are blank in open-auth captures because the profile has
  no values; they come from the authenticated user when present.
- Historical alert bodies can remain Hinglish; new P2 UI labels are English.
  The audit log was not rewritten.
- Per-tank DO and NTU calibration still do not exist; the UI keeps raw ADC
  labelled as raw ADC.
- The `p2-dashboard-mobile.png` is a viewport capture so the fixed bottom nav
  appears where a user actually sees it; it is not a stitched full-page image.
